# Mobile library and audio review — refreshed 0.2.5

The review traced the app-owned native code, WebView bridge, browsing and queue state, renderer integration, storage/scan paths, radio handling, manifest/network policy, build configuration and native/JVM checks. Bundled third-party library internals were not independently audited. Original desktop repositories were read for parity and were not modified for this mobile change.

| Path | Finding and resulting behavior |
| --- | --- |
| `NetworkSources` | Connection imported only 500 albums, omitted `getStarred2`, and treated favourites as device SQLite flags. It now pages the catalog through completion, imports all server stars, artists, playlists and radio stations, and stores a complete metadata snapshot. A failed refresh preserves the preceding completed snapshot. |
| `Library` / `MainActivity` | Device favourites could include cached remote tracks; remote hearts never changed server stars. Local favourite queries now exclude remote tracks. Remote hearts use `star` / `unstar`, and catalog/response summaries provide full source totals. |
| `NetworkSources` account identity | Track ownership now includes server URL and username. Existing cached track IDs used by device playlists are retained on migration; new account-scoped IDs prevent cross-account collisions. Authenticated stream URLs and credentials stay native. |
| `NavidromeAudio` / `PlaybackService` | Remote playback unconditionally requested raw files. The native loader now posts an Android decoder profile to `getTranscodeDecision`, consumes the opaque token through `getTranscodeStream`, and offers lossless FLAC or MP3 conversion when needed. Older servers retain an explicit raw/FLAC fallback. Network negotiation runs on the audio loader, rather than the main thread or the renderer. Existing native queue replacement, audio focus and background service remain in use. |
| `app.js` / CSS / bridge | Dropdown choices had secondary lines and no visible selected mark. All browser rows now have a single label, visible ticks and accessible selection state. Headers show a separator and numeric total without a redundant unit label. Counts follow favourite scope, empty selections, artist filtering, playlist imports and radio results. Longer full-library operations have an appropriate bridge timeout. |
| Favourite-song grouping | Grouping previously discarded the favourite selection and switched to full albums. It now groups only returned favourite tracks and queues them across the selected album order, preventing playback from pulling unstarred album tracks. |
| `RadioDirectory` / metadata details | Server radio stations were never imported. Saved stations now include the active server list, while local saves remain editable. Server radio editing is omitted from station actions. Track details use source-aware hearts and reject an unrelated account. |
| Scanner / renderer / manifest | Local music remains read-only. Local scans, indexed restoration, bounded artwork caching and renderer scheduling are preserved. The package, Android requirements, encrypted login storage, origin-scoped bridge, certificate validation and published HTTPS-only policy are retained. |

## Verification

The isolated Android 15 emulator fixture contains 501 albums, a starred album on page two, 301 favourite songs across two albums, two artists, two server playlists and two server radio stations. It checks complete imports, full header totals, ticks, compact rows, remote star/unstar, device/remote isolation, legacy playlist-track migration, encrypted login restoration and disconnect authorization.

Native audio checks use non-silent synthetic M4A/AAC, stereo 48 kHz WAV and FLAC files. A synthetic unsupported ALAC source exercises server conversion to FLAC. Both negotiated-stream and older-server fallback cases require selected audio tracks, nonzero and increasing rendered decoder-buffer counts, advancing playback, nonzero volume and no player error. Tests cover seeking, remote background playback and automatic transition from the last favourite in one album into the next favourite album with repeat/shuffle off. Existing local playback/mode/lifecycle and touch/layout suites also pass. Nine JVM checks and Android lint pass.

## Limits and operation

This fixes confirmed import and stream-selection defects. The Honor phone's exact model, Android version, original codecs and acoustic output were not available, so its reported silence is not claimed reproduced or certified resolved. Android codec behavior, speaker/headphone/Bluetooth routing and server transcoding configuration still require a handset listening check. Playback negotiation follows the [OpenSubsonic decision API](https://opensubsonic.netlify.app/docs/endpoints/gettranscodedecision/) and [stream API](https://opensubsonic.netlify.app/docs/endpoints/gettranscodestream/); device support follows [Media3 format support](https://developer.android.com/media/media3/exoplayer/supported-formats).

After installing over the existing APK, open the remote source or use Settings → Refresh Navidrome library. First upgrade loads complete remote metadata; manual refresh also imports changes made in the web app. Reopening/using a catalog older than five minutes refreshes it. Song browsing/search still uses 200-result pages, although totals and favourite imports are complete. Remote queues have a 10,000-track limit. Server playlists and radio stations are read-only, with no offline audio downloads. Imported HTTP radio addresses remain visible but require an HTTPS address for playback in the published build.

VersionName **0.2.5**, versionCode **8**, application ID and signing certificate remain unchanged. Installing the refreshed APK retains app data. No production or personal-server tests were run, and no credentials, signing keys or test TLS key are packaged in the release APK.
